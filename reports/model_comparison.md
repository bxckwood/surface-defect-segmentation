# Сравнение моделей и дополнительных запусков

## Исходные три модели

Сначала обучены три модели с одинаковыми `train/val/test` split, seed 42, размером изображения `[height, width] = [640, 256]`, batch size 8, 25 эпохами и AdamW с learning rate 0.0003 и weight decay 0.0001. Лучший checkpoint выбирался по IoU на `validation`. Для сравнения ниже все модели оценены на `validation` при **одинаковом пороге 0.5**. `Train loss` и `Val loss` взяты из строки лучшей эпохи `history.csv`.

| Модель | Loss | Pretrained encoder | Лучшая эпоха | Train loss | Val loss | Val IoU | Val Dice | Test IoU | Test Dice |
| --- | --- | --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| U-Net | BCE | Нет | 19 | 0.0081 | 0.0075 | 0.3359 | 0.5029 | — | — |
| U-Net | BCE + Dice | Нет | 25 | 0.1936 | 0.2787 | 0.4079 | 0.5795 | — | — |
| ResNet18 U-Net | BCE + Dice | Да | 23 | 0.1834 | 0.2187 | **0.4992** | **0.6659** | **0.4884** | **0.6562** |

Столбцы `Val` получены при пороге 0.5 у всех моделей; `Test` — только у выбранной ResNet18 U-Net при пороге 0.7, зафиксированном по validation. Численные значения loss у BCE и BCE + Dice напрямую не сравниваются: функции потерь различаются. Значения IoU и Dice рассчитаны по пикселям foreground.

## Ошибки на validation при пороге 0.5

| Модель | Ложные срабатывания на чистых изображениях | Пропущенные дефектные изображения |
| --- | ---: | ---: |
| U-Net, BCE | 11 из 417 (2.64%) | 13 из 49 |
| U-Net, BCE + Dice | 79 из 417 (18.94%) | 4 из 49 |
| ResNet18 U-Net, BCE + Dice | 58 из 417 (13.91%) | 3 из 49 |

Ложным срабатыванием считается чистое изображение, на котором модель выделила **хотя бы один пиксель**. Пропущенным считается дефектное изображение, на котором предсказанная маска **не пересеклась с разметкой**. При этом предсказание вне размеченного дефекта может присутствовать.

## Первый выбор модели и порога

ResNet18 U-Net показала наибольшие validation IoU и Dice при общем пороге 0.5. По сравнению с U-Net + BCE + Dice она дала меньше ложных срабатываний на чистых изображениях (58 вместо 79) и меньше пропусков дефектных изображений (3 вместо 4). U-Net + BCE дала наименьшее число ложных срабатываний (11), но и наименьшие IoU, Dice и обнаружение дефектных изображений. Поэтому для итоговой оценки выбрана `runs/resnet18_unet/best.pt` (эпоха 23).

После выбора checkpoint порог перебирался **только на validation**:

| Порог | 0.3 | 0.4 | 0.5 | 0.6 | 0.7 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Val IoU | 0.4956 | 0.4978 | 0.4992 | 0.5004 | **0.5015** |

При пороге **0.7** также получены validation Dice 0.6680, 52 ложных срабатывания из 417 чистых изображений (12.47%) и 3 пропущенных дефектных изображения из 49. Прирост IoU относительно порога 0.5 невелик (около 0.0024). Этот порог зафиксирован до оценки на `test`. Команда поиска порога из README создаёт локальный `runs/resnet18_unet/val_threshold_search.json`; папка `runs/` не входит в репозиторий.

Сравнение U-Net + BCE и U-Net + BCE + Dice показывает улучшение IoU и Dice при росте ложных срабатываний. Компонент Dice поощряет пересечение масок на изображениях с дефектом; это согласуется с уменьшением числа пропусков, но не доказывает причину различия. Их конфиги отличаются функцией потерь, однако один split и seed не позволяют оценить разброс от случайных аугментаций и порядка батчей. Предобученные признаки и другой encoder ResNet18 могли помочь выделять дефекты, но оба фактора менялись одновременно, поэтому по этому эксперименту нельзя оценить их вклад по отдельности.

## Оценка исходной модели на test

После фиксации модели и порога получены показатели `test` для `runs/resnet18_unet/best.pt` при пороге **0.7**. Для двух исходных U-Net показатели `test` не приводятся; результат нового варианта ResNet18 U-Net показан ниже.

| Test IoU | Test Dice | Ложные срабатывания на чистых | Пропущенные дефектные |
| ---: | ---: | ---: | ---: |
| **0.4884** | **0.6562** | 114 из 894 (12.75%) | 7 из 110 (6.36%) |

Команда оценки из README создаёт локальный `runs/resnet18_unet/test_metrics.json`. Test использован для итоговой оценки, а не для подбора модели или порога.

Возможные объяснения для проверки в будущем: фиксированный resize может уменьшать тонкие дефекты, а продольные структуры чистой поверхности могут быть похожи на дефект для модели. По четырём примерам подтвердить эти причины нельзя. Дополнительные запуски ниже проверяют только частоту дефектных снимков при обучении и learning rate. Поскольку этот `test` уже просмотрен, его повторная оценка описывает результат, но не даёт независимого подтверждения улучшения.

## Два запуска с семплированием

В исходном `train` дефект есть на 197 из 1865 снимков. В [первом новом конфиге](../configs/resnet18_unet_balanced.yaml) дефектные снимки выбираются с ожидаемой долей 25% вместо 10,6%. Семплер выбирает с повторением и делает 1865 подач за эпоху. [Второй новый конфиг](../configs/resnet18_unet_balanced_low_lr.yaml) отличается от первого только learning rate (0.0001 вместо 0.0003) и папкой результатов. Модель, loss, split, seed, batch size и число эпох не менялись. Оба запуска завершены за 25 эпох.

Лучший checkpoint каждого варианта выбран по IoU на `val` при пороге 0.5. Все три ResNet18 U-Net оценены при этом общем пороге с `--device cuda`:

| Вариант | Лучшая эпоха | Val IoU | Val Dice | Средний IoU на дефектных снимках | Ложные тревоги на чистых | Пропуски дефектов |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Исходная | 23 | 0.4992 | 0.6659 | 0.5317 | 58 из 417 | 3 из 49 |
| Семплер 25%, LR 0.0003 | 16 | 0.5604 | 0.7182 | 0.5280 | **20 из 417** | 5 из 49 |
| Семплер 25%, LR 0.0001 | 10 | **0.6173** | **0.7633** | **0.5454** | 45 из 417 | **2 из 49** |

![IoU и Dice пяти вариантов на validation](figures/validation_quality.svg)

![Validation IoU по эпохам для пяти вариантов](figures/validation_iou_epochs.svg)

![Ложные тревоги и пропуски на validation](figures/validation_error_rates.svg)

Первый новый запуск сократил число ложных тревог, но увеличил число пропусков. Второй улучшил IoU и число пропусков относительно обеих предыдущих ResNet18 U-Net; ложных тревог у него меньше, чем у исходной модели, но больше, чем у первого варианта с семплером. Это результаты отдельных запусков с одним seed, а не доказательство причины различий. Снижение learning rate не устранило колебания: у второго варианта validation IoU упал до 0.2277 на эпохе 19, хотя максимум 0.6173 достигнут на эпохе 10.

После выбора checkpoint пороги 0.3–0.7 перебраны только на `val`:

| Вариант | 0.3 | 0.4 | 0.5 | 0.6 | 0.7 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Семплер 25%, LR 0.0003 | 0.5560 | 0.5575 | 0.5604 | 0.5640 | **0.5667** |
| Семплер 25%, LR 0.0001 | 0.6000 | 0.6098 | 0.6173 | 0.6235 | **0.6287** |

При пороге 0.7 у второго варианта также получены validation Dice 0.7721, 33 ложные тревоги из 417 чистых снимков и 2 пропуска из 49 дефектных. [Истории обучения](histories/resnet18_unet_balanced_low_lr.csv) и [validation-метрики](resnet18_unet_balanced_low_lr_val_threshold_search.json) сохранены вместе с [результатами первого варианта](resnet18_unet_balanced_val_threshold_search.json).

## Повторная оценка на test

Для второго нового варианта зафиксированы checkpoint эпохи 10 и порог 0.7, выбранный на `val`, после чего выполнена оценка на официальном `test`. Для сравнения ниже приведён прежний результат исходного checkpoint при том же пороге:

| ResNet18 U-Net | Test IoU | Test Dice | Ложные тревоги на чистых | Пропуски дефектов |
| --- | ---: | ---: | ---: | ---: |
| Исходная | 0.4884 | 0.6562 | 114 из 894 | 7 из 110 |
| Семплер 25%, LR 0.0001 | **0.6047** | **0.7536** | **49 из 894** | **6 из 110** |

![Описательное сравнение исходной и новой модели на test](figures/test_comparison.svg)

Числа нового варианта сохранены в [test-метриках](resnet18_unet_balanced_low_lr_test_07.json). Улучшение на этом наборе наблюдается по всем четырём показателям таблицы. Однако `test` уже просматривался при анализе ошибок исходной модели; поэтому повторная оценка носит описательный характер. Независимую проверку можно провести только на новых отложенных данных. Опубликованный Release `v1.0.0` по-прежнему содержит checkpoint исходной модели; checkpoint второго нового варианта пока хранится локально в `runs/resnet18_unet_balanced_low_lr/best.pt`.
